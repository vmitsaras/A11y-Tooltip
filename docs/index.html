Accessible UI primitive

A tooltip that behaves like a tooltip.

Focus or hover a trigger. Move the pointer onto the tooltip if you need more time to read it. Press Escape to dismiss it without moving focus.

Get started

Initialize the plugin

Install the package, import its stylesheet, then choose the initializer that matches your page. The package never initializes automatically.

Initialize one tooltip

import { createTooltip } from "a11y-tooltip";
import "a11y-tooltip/styles.css";

const root = document.querySelector("[data-a11y-tooltip]");

if (root instanceof HTMLElement) {
  createTooltip(root);
}

Initialize every tooltip in a scope

import { initTooltipsAll } from "a11y-tooltip";
import "a11y-tooltip/styles.css";

initTooltipsAll({}, document);

Optional addon · CSS Anchor Positioning

Give descriptions room near an edge

Use createAnchorPositioningAddon() for controls in compact toolbars or near a viewport edge. It connects each tooltip to its trigger with native CSS Anchor Positioning and supplies placement-aware position-try fallbacks when the preferred side runs out of room. Browsers without the required CSS features keep the standard positioning. Pass fallbacks: [] to disable fallback attempts, or provide your own supported fallback tactics.

Focus or hover either trigger, then resize the window to explore the available space. Both examples prefer an outward-facing placement; fallback attempts depend on browser support and available room.

A left placement tries an inline flip first when space is limited. A right placement can try the opposite side without moving focus. 
import { initTooltipsAll } from "a11y-tooltip";
import { createAnchorPositioningAddon } from "a11y-tooltip/addons";
import "a11y-tooltip/styles.css";

initTooltipsAll({
  addons: [createAnchorPositioningAddon()]
}, document.querySelector("[data-demo-anchor]"));

Experimental addon · Native hint popover

Let supporting browsers render the hint in the top layer

Use createHintPopoverAddon() when a tooltip needs the browser's native popover="hint" behavior while preserving the A11y Tooltip interaction model. The addon activates only when hint popovers and the required CSS Anchor Positioning features are supported; otherwise the ordinary tooltip remains in place.

import { initTooltipsAll } from "a11y-tooltip";
import { createHintPopoverAddon } from "a11y-tooltip/addons";
import "a11y-tooltip/styles.css";

If custom Anchor Positioning fallbacks are needed, place createAnchorPositioningAddon({...}) before createHintPopoverAddon() in the addon list so the explicit positioning configuration is shared.

Optional addon · Overflow only

Reveal text only when it is clipped

Use createOverflowOnlyAddon() for truncated file names, table labels, or compact controls. By default it measures the trigger's inline overflow whenever opening is requested. A floating tooltip opens only when the text is clipped; the aria-describedby relationship stays intact either way.

Focus or hover the long file name to reveal its full text. Try Notes.txt for comparison: it fits, so no floating tooltip opens. After resizing, leave and return to a trigger to measure it again.

For nested labels, set target to a selector within the tooltip root. Use axis: "block" or axis: "either" for other clipping directions, and tolerance to ignore small differences in CSS pixels. Measurement happens on opening, without continuous observation.

Shared controller

Use one visual tooltip for a delegated selector

Use createSharedTooltip() when a toolbar, grid, or command surface has many already-named controls that only need visual hover and focus hints. The controller listens from one container, reads content from each matching trigger, and keeps the shared tooltip out of the accessible-name path.

Focus or hover any command below. Each button keeps its own aria-label; data-tooltip-text supplies only the shared visual hint.

Compare retarget motion

Use the motion buttons, then move focus or hover across the row. The Move mode uses WAAPI FLIP animation to travel from the previous command to the next one. 

import {
  createSharedTooltip
} from "a11y-tooltip/shared";
import "a11y-tooltip/styles.css";

const toolbar = document.querySelector("[data-demo-shared-toolbar]");
const motionToolbar = document.querySelector(
  "[data-demo-shared-motion-toolbar]"
);

if (toolbar instanceof HTMLElement) {
  const controller = createSharedTooltip(toolbar, {
    triggers: "[data-tooltip-text]",

    getContent(trigger) {
      return trigger.dataset.tooltipText ?? "";
    },

    placement: "bottom"
  });
}

if (motionToolbar instanceof HTMLElement) {
  const controller = createSharedTooltip(motionToolbar, {
    triggers: "[data-tooltip-text]",
    getContent(trigger) {
      return trigger.dataset.tooltipText ?? "";
    },
    motion: "move",
    motionDuration: 320,
    motionEasing: "ease-in-out",
    showDelay: 0,
    hideDelay: 300,
    placement: "bottom"
  });
  controller.tooltip.classList.add("shared-toolbar-motion__tooltip");
}

Accessibility contract

Use the right pattern

  • The trigger must be keyboard-focusable and independently named.
  • The tooltip is descriptive content referenced by aria-describedby.
  • The tooltip never receives focus and must not contain interactive controls.
  • Essential instructions should stay visible rather than living only in a tooltip.
